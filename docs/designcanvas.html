The canvas

One page, three agents, two regions. Cells are tagged by agent — Site AdvisorRoute AdvisorWatchdog — wherever they diverge; untagged text applies to all three.

Boundary

Three agents, split by job. Site Advisor and Route Advisor each read their own region's Atlas thresholds (urban 0.5/1mi vs. rural 10/20mi) and live OSM Overpass — both pinned in code by a config constant, never by argument. Neither writes anything; every tool is read-only plus one no-side-effect LLM call. Watchdog reads the same reference data plus one shared flagged-tracts log, and can write only to that one table. No personal data anywhere — every dataset is public, tract- or resource-level. No AgentCore Identity surface needed; nothing here authenticates as a person.

Stocks

Two parallel instances of the same stock, not summed: unclosed gaps in urban tracts (Site Advisor's) and in rural tracts (Route Advisor's) — different populations, different mechanisms. Both feed one shared Watchdog stock: rows in the flagged-tracts log, each awaiting confirmation that a resource, or a route change, actually happened.

Flows

In: tracts newly qualifying as low-access — environment-driven, no agent affects this. Out: a resource opens (urban) or a route/distribution day shifts to cover a tract (rural) — different in kind, same effect on the stock. Into the log: every top-ranked recommendation from either Advisor, tagged by source. Out of the log: a Watchdog-confirmed change — the only way a row closes.

Existing loop — broken how

Site AdvisorOrganizers can't easily cross severity data against what's already nearby, so siting runs on instinct instead of evidence that already exists.
Route AdvisorThe right response already exists — mobile markets, food-bank routes — but it's planned once and rarely re-optimized against current need. A coordination gap, not an information vacuum.
WatchdogOnce a recommendation is made, nothing ever checks whether it was acted on — a good call and a bad one look identical a year later: silence.

Leverage point

Site AdvisorRung 6, information flow — surface the crossed picture at the moment organizers decide.
Route AdvisorRung 6 again, pointed at route/schedule decisions instead of siting — plus rung 9, delay, shrinking an annual replanning cadence to quarterly.
WatchdogRung 8, negative feedback strength — escalate by re-checking on a schedule, don't just make one recommendation and hope.

Goal state

Unclosed gaps trending down in both regions, tracked separately, not pooled. Urban: shrinking median time from a Site Advisor recommendation to a Watchdog-confirmed resource. Rural: shrinking median time from a Route Advisor recommendation to a Watchdog-confirmed route change. Not zero food deserts anywhere — measurable movement, provably tracked, per region.

Loop design

All three agent-loops are balancing (human stays the actuator). Neither Advisor needs a governor on its core loop — each only surfaces evidence. Watchdog's governor is its recheck cadence. One shared reinforcing loop — trust/adoption — is governed everywhere by the decision-support framing guardrail, plus a second, rural-only reinforcing risk: a route has fixed capacity, so always favoring the single highest-need tract can zero-sum-starve tracts it already serves. Governed by requiring that trade-off to be disclosed in the output itself, not just implied.

Topology

Three agents, not two. Site Advisor and Route Advisor are siblings, not one agent with a region flag — on purpose, since a flag would reopen exactly the model-controlled surface the Step 8 fix closed. Each is one Agent calling tools in a fixed order (Workflow-shaped, not true Agents-as-tools). Watchdog is generalized to watch both — one accountability agent, not three — still split from the Advisors by lifecycle.

Memory

Same three-way split, now shared across three agents. Reference data is a queried knowledge base, not memory. Neither Advisor remembers anything beyond one turn. Watchdog holds the one genuine persistent state — the flagged-tracts log — now with a recommendation_type and source-agent column, so one table serves both Advisors instead of duplicating the mechanism.

Guardrails

Region boundary enforced in code for both Advisors identically: zero region/bounding-box arguments, each pinned to its own config constant (an earlier version silently accepted an unused argument; removed, not patched). Route Advisor adds one Site Advisor didn't need: the capacity trade-off must be disclosed in the output itself — a content rule, as real as the access rules, and worth actually testing for. Watchdog still writes only its own log. Every answer cites its data source + vintage and frames output as decision support.

Success metric

Per region, not pooled: reduction in unclosed gaps over the demo window, plus median days from recommendation to Watchdog-confirmed change. Rural adds a second number worth watching on its own: whether the capacity trade-off is actually being disclosed, not just whether a recommendation fires — a guardrail that's silently failing doesn't look broken, it just looks quiet.

Archetype risk

Fixes That Fail is still primary for Site Advisor + Watchdog — stale Atlas data, caught by the recheck. For Route Advisor, Success to the Successful is now primary, not secondary: fixed route capacity makes the zero-sum version of this archetype concrete rather than hypothetical. Limits to Growth applies to both, sharper for rural — a county-sized Overpass query is bigger and slower than a city one, closer to the shared public API's real limits.

Before you submit Walk this canvas once more against §05 of the blueprint. The archetype risk cell above is the answer to that check — if it ever stops feeling true, the design drifted and it's worth another pass, not a rewrite.
